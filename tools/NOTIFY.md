# NOTIFY.md —— 任务通知规范（写给 agent）

> 你是谁：在这个工作区里替用户执行任务的 agent。
> 你要做的事：**当你卡住、或任务完成时，用 `tools/notify.py` 推一条消息到用户微信。**
> 用户不在电脑前时，这条推送是他唯一能看到你的方式。

> **本文件是通知细节的唯一来源。** `AGENTS.md` 只是每次会话自动加载的薄入口（触发条件 + 命令 + 三条红线）。
> 要改规则、改命令、补坑，**只改这一份**，不要把细节复制回 `AGENTS.md`——两份重复迟早漂移。

---

## 1. 必须推的两种情况（P0，不能漏）

### A. 任务完成

判定：用户交代的目标已经达成，或本轮能交付的部分已经交付完毕。

推送后再给最终回复。**不要只写对话框、不推手机**——用户可能不在屏幕前。

### B. 卡住

判定（满足任一条即算）：

- 需要用户点审批 / 授权才能继续（**必须在弹审批之前推**，不要先等）
- 缺关键信息，只有用户能提供（账号、路径、选择、确认）
- 同一问题连续 2 次以上尝试仍失败
- 需要用户在两个方案之间做决定
- 你判断自己在等一个不会自动到来的东西

推完再等。等待期间不要重复推同一条。

### C. 可选（默认不推）

- 超过 30 分钟的长任务，阶段完成时可推一次
- 开始前预告（用户明确要求过才推）

---

## 2. 不要推的情况

- 中间步骤、工具调用结果、单步进度
- 你自己发现并修正了错误（结果正常就不必惊动用户）
- 同一事件已经推过
- 用户正在对话里实时回你（除非他明确说了离开）

原则：**宁可少推**。200 条/天的额度不是留给"我改了 3 个文件"的。

---

## 3. 怎么发

在工作区**根目录**执行，脚本走相对路径 `tools/notify.py`。`notify.py` 只用 Python 标准库（`urllib`/`json`/`pathlib`），**3.8+ 任意解释器都能跑，无第三方依赖**。

```bash
# macOS / Linux
python3 tools/notify.py -t "[DSH] 完成 · 报表整理" -c "结果: 12 个 sheet 已合并
产出: out/merged.xlsx
时间: 2026-10-17 23:05"
```

```powershell
# Windows PowerShell（PATH 里通常没有 python，用 DSH 自带运行时）
$py = "$env:DSH_HOME\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
& $py tools\notify.py -t "[DSH] 完成 · 报表整理" -c "结果: 12 个 sheet 已合并
产出: out\merged.xlsx
时间: 2026-10-17 23:05"
```

找解释器的兜底：`$DSH_HOME/dsh-runtimes/*/dependencies/python/` 下就是 DSH 的 Python（macOS 在 `bin/python3`，Windows 是 `python.exe`）。macOS 上系统自带的 `python3` 直接可用，不必找这个路径。

> bash/zsh 里正文用双引号时注意：`$`、反引号会被展开，正文里别写这些字符。

参数：

| 参数 | 说明 |
|---|---|
| `-t` | 标题，≤100 字 |
| `-c` | 正文，≤2 万字，换行直接写在字符串里 |
| `--channel` | 不填走配置默认（`wechat`）。可选 `wechat,qq,sms` |
| `--test` | 自检，发一条测试消息 |

判断结果：

- 输出 `[ok] wechat=OK` → pushplus 已受理（不代表手机一定弹了通知，但通常没问题）
- 输出 `[fail] wechat=FAIL(原因)` → 看括号里的原因

失败处理：

- **网络类错误**（timeout / Connection）→ 最多重试 1 次
- **业务类错误**（未实名 905 / 超额度 / 同内容重复）→ 不要重试，把原因写进给用户的最终回复
- **推送失败绝不能阻塞任务本身**，也不要为了推消息去申请提权

## 4. 消息怎么写

标题格式：`[DSH] <状态> · <对象>`

| 场景 | 标题示例 |
|---|---|
| 完成 | `[DSH] 完成 · 周报生成` |
| 卡住 | `[DSH] 卡住 · 等你审批删文件` |
| 待决策 | `[DSH] 待选 · 方案A还是B` |

正文 ≤4 行，包含：

1. 一句话结果 / 卡点
2. 需要用户做什么（没有就写"无需操作"）
3. 产出路径，或下一步
4. **时间戳**（必须带：规避平台"相同内容 1 小时最多 3 条"的去重）

模板：

```
完成：
结果: <一句话>
产出: <相对路径>
遗留: <无 / 具体说明>
时间: 2026-10-17 23:05

卡住：
卡在: <一句话>
需要你: <点审批 / 提供 X / 选 A 或 B>
影响: <不做会怎样>
时间: 2026-10-17 23:05
```

不要往正文塞：大段日志、完整报错栈、token、密码、隐私内容、多个不相关事项（合并成一条也比连发三条好）。

## 5. 平台限制（会咬人的）

| 项 | 限制 |
|---|---|
| 微信渠道 | 实名用户 200 次/天 |
| 请求频率 | 5 次/分钟 |
| 相同内容 | 1 小时最多 3 条 → 正文带时间戳 |
| 长度 | 标题 100 字，正文 2 万字 |
| 时机 | 整点 0 分 / 30 分易挤，可能延迟 |
| 未实名 | 接口返回 905，任何渠道都发不出 |

---

## 6. 环境坑

### 6.1 通用（两边都适用）

1. **不要为发通知去申请 danger-full-access**。发通知只需要出网，不需要提权。
2. `notify.py` 只读配置 + 发 `POST`，不写任何东西到工作区（日志是追加写，失败会兜底到临时目录）。
3. `tools/notify.config.json` 是唯一的秘密文件；日志里只会有标题和渠道，没有 token。

### 6.2 Windows 沙箱特有（**macOS / Linux 上不成立，别当通用结论**）

1. **子进程写不了工作区**：新建文件报 `ENOENT`、追加写报 `EBADF`；临时目录正常。
   → 脚本日志自动兜底到 `%TEMP%\dsh-notify.log`。
   → 不要在 Windows 上试图往工作区写临时文件/心跳文件，会失败。
2. **curl / `Invoke-WebRequest` 出网被限制**（schannel 无凭证）。发 HTTP 用 Python 或 Node。
3. `notify.py` 里的日志兜底逻辑就是为这个坑写的，macOS 上不会触发。

> 换平台后先跑一次 `--test`：通了就说明该平台的出网与写权限都正常，不必照搬上面的 Windows 结论。

---

## 7. 安全

- token 在 `tools/notify.config.json`：**不要打印、不要回显、不要粘贴到任何会被分享或提交的文件里**。
- 推送正文不要包含密钥、身份证、完整本地路径以外的隐私数据。
- 这个 token 谁拿到谁就能给用户推消息（无二次验证），别外传。

---

## 8. 自检

```bash
# macOS / Linux
python3 tools/notify.py --test

# Windows PowerShell
$py = "$env:DSH_HOME\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
& $py tools\notify.py --test
```

预期 `[ok] wechat=OK`。发不出去时按这个顺序查：是否关注服务号「pushplus 推送加」→ 是否 905（未实名）→ 是否超 200/天 或 5 次/分钟 → 是否内容 1 小时内重复。
